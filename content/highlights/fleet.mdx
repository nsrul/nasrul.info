I wanted to stop treating each agent CLI as its own window. Fleet puts Claude Code, Codex, Cursor Agent, Gemini CLI, OpenCode, and plain shells in one place: a sidebar of sessions, two live terminal panes, and a context panel that follows what the focused agent is changing.

Fleet is not a wrapper around those tools. Each agent uses its own credentials and talks to its provider directly. Fleet owns the process and gives you a real terminal to talk to it through.

## The window is not the process

The daemon is a separate Rust process, `fleet-daemon`. It starts each session on a PTY and serves a versioned Unix-socket API to the app. SwiftUI draws the shell and SwiftTerm handles terminal emulation, so escape sequences, Unicode, selection, scrollback, and resize behave like a terminal rather than a chat log.

Because the app is only a client, quitting it detaches the view and the agents keep running. Relaunch and you attach back to the same sessions; the PTY grid is resized through the daemon. That separation took more machinery than putting terminals inside a window: an engine, a protocol, PTY ownership, and a reconnect flow. It is still the part I would keep.

## What is still rough

This is a 0.1.0 prototype, and the honest parts are the useful ones. Session state lives in memory, so a daemon restart ends everything. Attaching to an old session replays a bounded output backlog instead of restoring an exact screen. There is one project at a time, no worktree management, and the build is Apple Silicon only and ad-hoc signed.

The code is MIT licensed on [GitHub](https://github.com/nsrul/fleet), and the [0.1.0 release](https://github.com/nsrul/fleet/releases) ships a dmg. The next pass should be terminal snapshots, ordered replay, and a session list that updates when another client creates one.
